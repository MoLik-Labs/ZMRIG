## What each switch turns into

| You choose | The installer receives |
| --- | --- |
| Coin | `--algo rx/wow` — Monero adds nothing, because a switching pool may move the rig |
| Wallet | `--wallet <address>` |
| Rig name | `--rig-id <name>` |
| Pool | `--pool <host:port>` or `--pool tls://<host:port>` |
| Backup pools | `--failover <host:port>,<host:port>` |
| Fixed engine | `--engine zmrig` or `--engine xmrig` (absent = automatic) |
| Profile | `--profile free` by default (maximum hashrate); `--profile watt` is an explicit power-efficiency trade-off |
| 443-only network | `--cloudflare --ws-path <path>` |
| Proxy | `--proxy <url>` |
| Pool name filtered here | `--connect-to <host:port>` |
| Host refuses MSR writes | `--no-msr` |
| Rented hash | `--nicehash` |
| Do not tune the host | `--no-tune` |
| No thread search | `--no-autotune` |
| Keep the config | *(no `--force`)* |

Two rules are worth knowing because they change the command rather than just
adding a flag:

- Asking for WebSocket or a proxy forces `--engine zmrig`. The C++ engine has no
  WebSocket client and no proxy support, so the alternative would be a config
  nothing can run.
- A TLS pool becomes part of the `--pool` value (`tls://host:port`), because
  that is the form `oneclick.sh` parses.

The address you type is validated before the copy button unlocks. For Monero the
page decodes it: 95 characters (106 for an integrated address), the base58
alphabet, the network byte, and the four-byte Keccak-256 checksum every address
carries. A character swapped for another valid base58 character is refused —
that is the typo a character count cannot see, and the one that costs a week of
hashing. It is the same decoder the pool and the bot use (`lib/address.js`),
compiled into this page, so the three cannot disagree.

```console
builder.wallet.checksum   One character is wrong: the checksum does not match.
```

A stagenet or testnet address is a valid address that a mainnet pool cannot pay,
and the page says so instead of calling it a typo.

For the other six coins the check is the alphabet and a plausible length, plus a
warning when the prefix is not the one this site knows — it does not pretend to
verify a checksum it never computes. A pool host is validated as `host:port`, and
a full `stratum+tcp://…` URL pasted from a provider page is accepted.

The coin decides two things. It pins the algorithm (`--algo rx/wow` and so on) —
except for Monero, where adding the flag would stop a switching pool from moving
the rig to whichever RandomX coin pays best. And it decides whether a pool preset
is offered: the seven presets are Monero pools, so every other coin asks you for
its endpoint instead of inventing one. [Other coins](/docs/pools/coins) has the details and the commands.

The proxy field wants the whole URL — `socks5://host:port` or
`http://user:pass@host:port` — because that is what the miner parses. The dial
address is `host:port` only; it replaces the resolved IP but keeps the pool's
hostname in SNI and the `Host` header, which is the point: a name blocked by a
local resolver still works if you know where it lives.

## Preview first

The preview button copies the same command with `plan` in place of `install`.
`plan` resolves the pool, the engine, the profile, the huge-page strategy and
the autotune plan, prints them, and stops. It writes nothing.

Neither command contains your wallet's private anything: a public address is the
only credential involved, and it is visible to the pool by design.
